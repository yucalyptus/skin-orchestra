# 生化学で見る美容医療 ― 皮膚の下のオーケストラ

*An Orchestra Beneath the Skin: The Biochemistry of Aesthetic Medicine*

美容皮膚科医・美容医療従事者向けに、**細胞生物学・生化学の基礎を思い出し、自分たちが美容でやっている施術が細胞・分子レベルで何をしているのかを理解する**ための教材です。

「新しい知識の詰め込み」ではなく **学び直し**。臨床でふだん意識しない基礎を、施術と結びつけて腑に落とすことを目的にしています。

## 全体を貫く流れ

> 細胞の構造 → エネルギー代謝 → 品質管理 → 加齢変化 → 美容施術への応答

前半は治療を前面に出さず基礎を積み、**美容治療はセクション「美容皮膚科」から接続**します。

## 構成

```
Ⅰ 基礎 ― 細胞のしくみを思い出す
    細胞の地図 / 情報をどう読むか / エネルギー /
    材料を感知し作る / 掃除と作り直し / 傷つくとどうなるか / 加齢で何が変わるか
Ⅱ 美容皮膚科 ― 局所に施術する
    皮膚・脂肪・筋の生化学（治療は出さない） / 外用 / 注射 / デバイス
Ⅲ 美容内科 ― 全身から入れる
おわりに
```

**本数はここに書かない**（書くと必ず古くなる）。章ごとの一覧は **[`資料/章一覧.md`](資料/章一覧.md)**（自動生成）が持ちます。

- **治療は手段で分けています**（外用／注射／デバイス）。部の見出しが臨床の語彙になり、**新しい章の行き先が一意に決まる**ためです。
- **主訴（しみ・たるみ・赤み）では分けません。** 1本の章が複数の主訴にまたがるからです（IPLはしみと赤み、フラクショナルはたるみ・毛穴・小じわ）。主訴からは**索引ページ**で引きます（front matter の `適応:` を使う。索引ページ自体はまだ実装しておらず、分類軸も未決）。
- 美容皮膚科と美容内科の境目は投与経路ではなく、**標的が皮膚の特定構造か、全身か**です。内服でもトラネキサム酸は美白外用の章、イソトレチノインは皮脂の章にあります。

## この教材に章番号はない

章は **`id`**（英字）で指し、`id` がそのまま公開URLになります（`glycolysis` → `glycolysis.html`）。

- **章を足す＝`目次.yml` に id を1行足すだけ。**他は何も動かない。
- 章を挿入・分割・並べ替えしても、ファイル名も相互参照も図もURLもずれない。
- 読者にも章番号は見せません。位置は部の見出しと並び順が示します。
- **本文には順序語（「次章」「前章」）を書きません。**「次に何を読むか」はビルドが `目次.yml` から自動で出します。

## 少しずつ公開する

**著者が読んで確定した章だけを公開します。**週ごとに増えていく形です。

| コマンド | 出力 | 中身 |
|---|---|---|
| `python3 build.py` | `docs/`（公開用） | **`status: approved` の章だけ** |
| `python3 build.py --preview` | `_preview/`（ローカル専用） | **全章**。statusバッジ付き |

`_preview/` は `.gitignore` に入っているので、公開されることはありません。著者のチェックはこちらで行います。
未公開の章は、目次に薄く「準備中」と出ます（リンクなし）。未公開章への `[[id]]` は、公開ビルドで自動的にリンクが外れ、章題だけが残ります。

**公開の順番は決めていません。**著者が確認できた章から、**手動でビルドして push** します（GitHub Actions での自動化は未定）。だから読者には「いつ何が増えたか」が見えている必要があります。章を直したら front matter の `history:` に1行足すだけで、目次のNEW/更新バッジ・章ページの日付・更新履歴ページ・表紙の「最近の更新」をビルドが作ります。**バッジは手で貼りません。**

## 章の書き方

各章の先頭に front matter（`id`・`title`・`kind`・`status` ほか）を置き、**本文に H1（`# 章題`）は書きません**。他章は `[[glycolysis]]` で参照します（存在しない id を書くとビルドが止まります）。

**`id` は一度公開したら変えません。**変えると読者のリンクが切れます。`title` やファイル名はあとから変えても壊れません。

書式の詳細と執筆の規約は **[`CLAUDE.md`](CLAUDE.md)** が正典です。

## 画像について

本文からは次の記法で参照します。

```
![図の説明](figures/glycolysis_乳酸の行き先.png)
```

命名規則は `<章id>_<図名>.png`。図名の部分は日本語で構いません。1章に複数図を持てます。
`![…]` の説明文がそのままHTMLのキャプションになります。

| ディレクトリ | 形式 | 役割 |
|---|---|---|
| **`figures/`** | PNG | **ソース（正）**。本文mdはここを参照。画像を追加/差し替えるのはここ |
| **`docs/images/`** | **WebP** | **公開用**。ビルドが自動生成するので手で編集しない |

流れは **`figures/`（ソースPNG）→ ビルド → `docs/images/`（公開WebP）** の一方向です。

## ビルド方法

```
python3 gen_index.py                  # 資料/図版台帳.md・資料/章一覧.md を再生成
.venv/bin/python build.py             # 公開ビルド（approved のみ）→ docs/
.venv/bin/python build.py --preview   # 全章プレビュー → _preview/
```

**`.venv` は Pillow を入れた作業用の仮想環境**です（`.gitignore` 済み。マシンごとに作ります）。

```
python3 -m venv .venv && .venv/bin/pip install -q Pillow
```

PNG→WebP(q85) の変換に Pillow が要ります（容量が約1/8）。無いと画像がPNGのまま公開されてサイトが肥大するため、`build.py` は Pillow の無い python では**冒頭で止まります**（Pillowを持つ別のpython3が見つかれば自動で切り替えます）。止まったら `python3 -m pip install --user Pillow`。PEP 668 で弾かれる場合（Homebrewのpython）は一時venvが安全です。

**ビルド後は `git status` を見て、`docs/images/` に `.png` が混入していないか確認してください。**`.png` が追加され `.webp` が消えていたら、それが Pillow 無しで流した事故です。
