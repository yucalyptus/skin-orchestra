**このファイルは、新しいセッションが最初に読むもの。**「何が決まっていて、次に何をするか」だけを書く。
作業が進んだら、済んだ段を「済」にして、決定事項を足す。

## 1. なぜ作り直したのか

旧プロジェクト（`~/Desktop/黄先生宿題`／GitHub `yucalyptus/biyou-cell-textbook`）には2つの問題があった。

1. **章番号が邪魔だった。** 章を1本足すたびに、ファイル名・本文の相互参照・図・公開URLが全部ずれる。テーマの区分けは要るが、章に固定番号は要らない。
2. **チェックが追いつかないまま全57章が公開されていた。** 著者が読んで確定した章から順に、少しずつ出したい。

根はどちらも同じで、**「順番」と「公開状態」がファイルの中に埋め込まれていた**こと。両方をファイルの外に出す。

旧プロジェクトは**凍結して残す**。移行後の執筆・修正は**この新プロジェクトでのみ**行う。

| 未公開章 | 目次に**薄く「準備中」**で表示（リンクなし） |
| 更新情報 | **NEW/更新バッジ・章ページの日付・更新履歴ページ・表紙の「最近の更新」**（RSSは当面作らない） |

### 構成（2026-08-14 著者と決定）

```
Ⅰ 基礎 ― 細胞のしくみを思い出す                        26本
    細胞の地図 / 情報をどう読むか / エネルギー /
    材料を感知し作る / 掃除と作り直し / 傷つくとどうなるか / 加齢で何が変わるか
Ⅱ 美容皮膚科 ― 局所に施術する                          27本
    皮膚・脂肪・筋の生化学（9・治療は出さない）
    外用（3） / 注射（6） / デバイス（9）
Ⅲ 美容内科 ― 全身から入れる                             3本
おわりに                                                  1本
```

- **治療は手段で分けた**（外用／注射／デバイス）。部の見出しが臨床の語彙になり、新章の行き先が一意に決まるため。
- **主訴（しみ・たるみ・赤み）では分けない。** 1本の章が複数の主訴にまたがる（IPLはしみと赤み、フラクショナルはたるみ・毛穴・小じわ）ため、目次の骨には使えない。**front matter の `適応:` から索引ページを自動生成して回収する。**
- **美容皮膚科と美容内科の線引きは投与経路ではない。** 標的が皮膚の特定構造なら美容皮膚科、全身に入れて全身を動かすなら美容内科。だから内服でも tranexamic acid は `skin-lightening`、isotretinoin は `sebum` に置く。
- **美容内科は「増える箱」。** 今は3本だが、GLP-1・プラセンタ・ホルモン・経口サプリの行き先になる。

## 3. 設計

### 章の正体は front matter の `id`

```yaml
---
id: glycolysis
title: 解糖系
subtitle: glycolysis          # 英語または短い副題（任意）
kind: basic                   # basic（基礎）/ applied（各論）/ conclusion
status: draft                 # draft → review → approved
published: 2026-08-20         # 初公開日（approved にしたとき入れる）
updated: 2026-09-03           # 直近の更新日（任意）
history:                      # 更新履歴ページとバッジの元データ
  - {date: 2026-08-20, note: 初公開}
---
```

**ファイル名は自由**（日本語でよい）。システムが見るのは `id` だけ。

### 順番は `目次.yml` 1本だけ。構造は2階層

```yaml
sections:
  - section: 美容皮膚科
    subtitle: 局所に施術する
    parts:
      - part: 注射
        intro: 分子を組織に直接置く治療です。置く・誘導する・止める・壊す——…
        chapters: [ha-filler, biostimulators, ...]
```

- `part` を持たない `section` は、章を直下に置く（美容内科・おわりに）。
- **`intro` は部の扉としてビルドが出す。** 部を並べ替えても説明が部についてくる。

### 本文は並び順に依存させない（2026-08-14 決定）

構成を組み替えたとき、章末の送り文44か所が壊れた。原因は本文が順序を前提に書かれていたこと。以後：

| 書かないもの | 代わりに |
|---|---|
| 「次章」「前章」 | `[[id]]` で章題を明示する |
| 「第N章」「第N部」 | `[[id]]` ／ 部名・セクション名 |
| 「ここで◯◯の部は終わりです」「ここから△△に入ります」 | **書かない。** `目次.yml` の部 `intro` に持たせる |
| 「◯◯の最後は」「◯◯以降で」 | 「◯◯の各章で」 |

**章末の送り文は「内容の対比」だけを述べる。** 「[[biostimulators]]では、同じ注射でも体積の主役が変わります」は位置ではなく関係を言っているので、並べ替えても壊れない。
**「次に何を読むか」はビルドが目次.yml から自動で出す**（ページ送り）。本文には書かない。

### 公開ゲート

| コマンド | 出力 | 中身 |
|---|---|---|
| `python3 build.py` | `docs/`（公開） | **status: approved のみ** |
| `python3 build.py --preview` | `_preview/`（gitignore・ローカル専用） | **全章**。statusバッジ付き |

### 週次の運用

1. 著者がプレビュー（またはmd）を読む → 指摘 → 修正
2. OK → `status: approved`、`published:` に日付、`history:` に1行
3. `python3 build.py` → commit → push（pushは毎回確認を取る）
4. 更新履歴・バッジ・表紙の「最近の更新」に自動で載る
